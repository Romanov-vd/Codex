# Лабораторная работа по компьютерной графике

Один проект на C++17 и один общий отчёт для вариантов 1–3.
Номер работы в отчёте — **2**, как внутри задания `lab_1.pdf`.

Реализованы Лаплас, Робертс, Собел; арифметическое усреднение 3×3 и 5×5;
гауссово усреднение 5×5 (σ=1); медиана 3×3 и 5×5; минимум и максимум 3×3.
Интерфейс `Image.h` взят из задания и не расширен.

## Сборка и запуск

Нужен компилятор C++17. Библиотеки уже лежат в `include`, скачивать их не требуется.

Linux, из корня проекта:

```sh
make -j2
make test
make demo
```

Windows, терминал PowerShell с установленным MinGW-w64:

```powershell
New-Item -ItemType Directory -Force build
g++ -std=c++17 -O2 -Iinclude src/Image.cpp src/Processing.cpp src/main.cpp -o build/lab.exe
g++ -std=c++17 -O2 -Iinclude src/Image.cpp src/Processing.cpp tests/tests_image.cpp tests/tests_processing.cpp -o build/tests.exe
./build/tests.exe
./build/lab.exe input/shapes_noisy.png output/shapes_noisy
```

В Visual Studio можно создать два консольных проекта C++17: приложение
(`Image.cpp`, `Processing.cpp`, `main.cpp`) и тесты (`Image.cpp`, `Processing.cpp`,
оба файла из `tests`). Добавить `include` в каталоги включения. Не подключать
`main.cpp` и `tests_image.cpp` к одному исполняемому файлу: в каждом свой `main`.
Запускать приложение из корня проекта с двумя аргументами: путь PNG и каталог результата.

Обработка своего изображения:

```sh
./build/lab input/my_image.png output/my_image
```

Программа запускает все методы и сохраняет 11 PNG. Цветной вход автоматически
переводится в градации серого. На границах повторяется ближайший пиксель.
Ошибки чтения/записи завершают программу с кодом 1.

## Содержимое

- `src`, `include` — исходники и библиотеки задания;
- `tests` — 12 тестов преподавателя и 6 дополнительных;
- `input` — два чистых эталона и их версии с гауссовым шумом;
- `output` — результаты обработки всех четырёх входов;
- `reports/Отчет.docx`, `reports/Отчет.pdf` — один общий отчёт в двух форматах;
- `reports/metrics.json` — измеренные MSE, PSNR и смещение яркости;
- `tools` — воспроизведение изображений и сборка отчёта (для запуска программы не нужны).

В титульном листе нужно вписать ФИО и группу. Подтверждено: 18 тестов,
474 проверки, все пройдены; четыре демонстрационных запуска, 44 выходных PNG.

## Подготовка иллюстраций

Сцены созданы самостоятельно. Гауссов шум добавлен **редактором ImageMagick**, а не
программой фильтрации: `-attenuate 0.9 +noise Gaussian`, глубина 8 бит,
seed 731 и 1201. Это соответствует разрешению другого редактора в варианте 2.
В варианте 3 отдельно назван Photoshop: здесь использованы те же изображения
из ImageMagick, что прямо отмечено в отчёте. Если преподаватель требует именно
Photoshop, это различие необходимо согласовать либо подготовить входы в нём
и повторить обработку и анализ. Использование Photoshop не заявляется.

Дополнительные скрипты требуют Python 3, Pillow, NumPy, python-docx, ReportLab;
для добавления шума нужен ImageMagick. Они не нужны для сборки C++ и уже готового отчёта.
`python3 tools/prepare_images.py` повторно создаёт входы; затем `make demo`
и `python3 tools/make_report.py` пересобирают результаты и отчёт в Linux.
При замене входных изображений следует также проверить текстовые выводы:
они описывают именно приложенные сцены, а таблицы вычисляются из PNG.
