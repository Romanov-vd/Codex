# Лабораторная работа №2. Цифровая обработка изображений

Одна программа на C++17 и один общий отчёт для всех трёх вариантов.
По объёму выполненных вариантов работа рассчитана на 4–5; оценку определяет преподаватель.

- Вариант 1: операторы Лапласа, Робертса и Собела.
- Вариант 2: арифметическое среднее 3×3 и 5×5, Гаусс 5×5 при σ=1.
- Вариант 3: медиана, минимум и максимум с окнами 3×3 и 5×5.

## Открытие в Visual Studio 2022

1. Установить компонент «Разработка классических приложений на C++» (MSVC v143 и Windows SDK).
2. Распаковать весь проект и открыть `Lab.sln`.
3. Назначить `Lab` запускаемым проектом, выбрать `Debug`, `x64` и нажать **Ctrl+F5**.
4. Открыть изображения в `test_output/shapes_noisy`.

Без аргументов обрабатывается `test_input/shapes_noisy.png`, эталоном служит
`test_input/shapes.png`, если он существует. Рабочий каталог уже настроен на папку решения.
Для тестов назначить запускаемым проект `Tests` и нажать Ctrl+F5.

Для своего входа в свойствах `Lab` → «Отладка» → «Аргументы команды» указать:

```text
test_input/detail_noisy.png test_output/detail_noisy test_input/detail.png
```

Третий путь — необязательный чистый эталон для расчёта MSE и PSNR.
Если его нет, достаточно первых двух путей. Все три варианта выполняются за один запуск.

## Сборка в Linux

```sh
make -j2
make test
make demo
make run
```

Альтернатива с CMake (также доступна в Visual Studio через открытие папки):

```sh
cmake -S . -B build/cmake
cmake --build build/cmake
ctest --test-dir build/cmake --output-on-failure
```

Требуется только компилятор C++17; библиотеки PNG и doctest включены в `include`.
Сборка и тесты проверены в Linux. Запуск MSVC под Windows в облаке не выполнялся.

## Функции и файлы

`Image.h` — неизменённый интерфейс из задания. `Image.cpp` отвечает за PNG,
память, глубокое копирование и безопасный доступ к пикселям. `setColor` ограничивает
яркости диапазоном 0–255 и сохраняет альфа-канал.

Алгоритмы находятся в `Filters.h/.cpp`:

| Функция | Назначение |
| --- | --- |
| `convertToGrayscale` | Перевод в полутоновое изображение |
| `laplaceEdges`, `robertsEdges`, `sobelEdges` | Выделение контуров |
| `meanFilter` | Арифметическое среднее |
| `gaussianFilter` | Гауссово усреднение |
| `medianFilter` | Выбор медианы окна |
| `minimumFilter`, `maximumFilter` | Выбор минимума и максимума окна |
| `calculateMSE`, `calculatePSNR` | Сравнение с чистым эталоном |

Названия файлов результатов соответствуют методам: `laplace_edges.png`,
`mean_3x3.png`, `gaussian_5x5.png`, `median_3x3.png`, `minimum_5x5.png` и т. д.
Каждый запуск сохраняет **13 PNG**. При наличии эталона дополнительно создаётся
`metrics.csv`: шумный вход и девять результатов подавления шума. Контурные карты
с эталоном по MSE не сравниваются.

Вызовы фильтров и размеры окон видны в `runFilters` файла `Source.cpp`.
Окна должны быть нечётными, от 1 до 31; сигма Гаусса — положительной и конечной.
На краях повторяется ближайший пиксель. Вход не меняется, каждый результат — отдельный Image.
Ошибки чтения, записи, эталона и аргументов печатаются в консоль; код завершения — 1.
Файлы, сохранённые до ошибки, остаются. Повторная обработка заменяет одноимённые результаты.
Для сравнения запусков с разными параметрами используйте разные каталоги выхода.

## Дополнительный случайный тест

```sh
./bin/app --random 73
./bin/app --help
./bin/app test_input/detail_noisy.png test_output/detail_noisy test_input/detail.png
```

`--random [seed]` создаёт градиентный фон, шесть случайных прямоугольников,
тонкие штрихи и гауссов шум со стандартным отклонением 18. Размер — 320×224.
По умолчанию seed=2026. Чистый и шумный входы сохраняются в
`test_input/generated/<seed>`, результаты и метрики — в `test_output/random_<seed>`.
Если готовый вход для запуска без аргументов отсутствует, создаётся такой дополнительный тест.
Один seed повторяет тест в одной сборке; совпадение между разными компиляторами не гарантируется.
Это вспомогательная демонстрация; для отчёта используются подготовленные в редакторе входы.

## Отчёт, изображения и подготовка

- `test_input` — две сцены 256×192: крупные фигуры и тонкие детали, чистые и с шумом.
- `test_output` — 52 демонстрационных PNG и CSV для двух шумных входов.
- `reports/Отчет.docx`, `reports/Отчет.pdf` — общий отчёт с содержанием и приложениями.
- `reports/metrics.json` — независимо пересчитанные из PNG показатели для отчёта.
- `preparation` — памятка простым языком: 67 вопросов с ответами, примеры и порядок показа.
- `tests` — 12 случаев из задания и 9 дополнительных: **21 случай, 384 проверки, все пройдены**.

Постановка задачи и заключение отчёта имеют одни и те же пункты в одинаковом порядке:
в заключении формулировки заменены на выполненные действия. Оформление — чёрный
Times New Roman 14, без гиперссылок. На титульном листе нужно вписать ФИО и группу.

Гауссов шум для приложенных сцен добавлен в **ImageMagick**:
`-attenuate 0.9 +noise Gaussian`, seed 731 и 1201, глубина 8 бит.
Для варианта 2 другой редактор прямо разрешён. Для варианта 3 исходное задание
буквально указывает **Photoshop**: для строгого выполнения этого пункта нужно
подготовить шумный вход в Photoshop. Приложенные входы не выдаются за созданные в нём.
После замены входов следует повторить обработку, пересобрать отчёт и проверить выводы по данным.

Скрипты оформления не нужны для сборки C++. Для их запуска нужны Python 3,
Pillow, NumPy, python-docx, pypdf; для изображений — ImageMagick,
для формул Word — Pandoc, для PDF — LibreOffice, TeX Live (pdflatex, amsmath, preview) и Poppler (pdftoppm), шрифты Times New Roman и Consolas.
Формулы сохранены как редактируемые уравнения Word со шрифтом Cambria Math.
Для PDF те же формулы набираются TeX и вставляются с разрешением 450 dpi:
это обходит ошибку отображения скобок OMML при экспорте LibreOffice.

```sh
python3 tools/prepare_images.py
make demo
python3 tools/make_report.py
python3 tools/make_preparation.py
```

Таблицы вычисляются из изображений; текст анализа описывает приложенные сцены,
поэтому после замены изображений его следует проверить отдельно.
